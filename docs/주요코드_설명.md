## 2. 화물 등록 → 기사 제안까지 (한눈에)

```
화주 등록 (POST /shipper/orders)
  ① 서버 적재 검증      packer.service.plan()          → 전량 적재 + 규칙 위반 없음일 때만 등록
  ② 매칭 라운드          matching_service._matching_round()  (Redis 분산 락 안)
       ├ 하드 필터        승인 · 노란 번호판 · 블랙리스트 · 기사 톤수 ≥ 필수 톤수 · PostGIS 반경
       ├ 차량별 적재 재계산  _fit() → 그 기사 차량에 정말 다 실리는가 (차종별 캐시)
       ├ 점수            규칙(거리 60% + 적재율 40%) 70% + LightGBM 수락 예측 30%, 0.75 미만 제외
       └ 최적 배정        hungarian.assign()  대기 화물 전체 × 빈 차 전체
  ③ 제안 → 기사 수락 (60초 안) → 배차 확정 / 거절 · 시간 초과면 다음 라운드에서 다음 기사
```

| 단계 | 팔레트 혼적 63상자 | 콜드체인 58상자 | 다중 하차 29상자 |
|---|---:|---:|---:|
| ① 서버 적재 검증 | 171 ms | 80 ms | 49 ms |
| ② 매칭 라운드 전체 | 284 ms | 314 ms | 110 ms |
|   ㄴ 차량별 적재 재계산 | 271 ms | 300 ms | 96 ms |
|   ㄴ 도로 거리 (112회) | 5.5 ms | 5.6 ms | 5.4 ms |
|   ㄴ LightGBM 예측 | 1.5 ms | 1.7 ms | 2.0 ms |
|   ㄴ **헝가리안 배정** | **< 0.1 ms** | **< 0.1 ms** | **0.1 ms** |

| 적용 단계 (`stage`) | 규칙 | 의미 |
|---|---|---|
| `place` 배치 중 차단 | R1~R9 | 어기는 자리에는 아예 놓지 않음 |

- 미적재 사유도 `"R5 지지면 부족 (공중 부양 위험)"`처럼 규칙 번호로 나옵니다.

### 3-2. Extreme Point 탐색 + R10 좌우 균형
[`engine.py`](../backend/engines/packer/engine.py) — Crainic · Perboli · Tadei (2008) Extreme Point 휴리스틱

```python
def _first_fit(self, box, eps, fails):
    for ep in eps:                                   # 후보점(EP)을 우선순위(벽 쌓기 / 바닥 우선) 순서로
        best = None
        for dx, dy, dz in box.orientations():        # 허용 방향 (세움 고정이면 수직축 회전만 = R3)
            cand = self._try(box, ep, dx, dy, dz, fails)   # R1 경계 · R2 겹침 · R5 지지 · R6 하중 · R7 · R8
            ...
        if best:
            cand = best[1]
            if self.o.balance:                       # R10: 같은 줄 반대편에도 놓아 보고
                alt = self._mirror(box, cand)
                if alt is not None and self._lateral_after(alt) + EPS < self._lateral_after(cand):
                    alt.balanced = True
                    return alt                       # 좌우 무게중심이 가운데에 더 가까운 쪽
            return cand
```

- **EP(Extreme Point):** 상자를 놓은 뒤 세 모서리를 벽 · 다른 상자 쪽으로 '투영'해 새 후보점을 만듭니다. 이미 놓인 상자 모서리만 쓰는 방식보다 빈틈을 잘 찾습니다.
- **R10 반대편 배치:** EP는 왼쪽 벽부터 채워서 그대로 두면 한쪽으로 쏠립니다. 같은 x · z 줄에서 오른쪽 벽(또는 오른쪽 상자 옆)에 붙인 자리도 시험해 무게중심이 가운데로 오는 쪽을 고릅니다.
- **충돌 · 지지면 검사는 numpy 벡터 연산:** 이미 놓인 상자 전체와 한 번에 비교합니다.

```python
# R2 비중첩 — 놓인 상자 k개와 한 번에
if k and np.any((X0 < x + dx) & (X1 > x) & (Y0 < y + dy) & (Y1 > y) & (Z0 < z + dz) & (Z1 > z)):
    fails["space"] += 1
    return None
```

```python
# R9: 엔진이 처음부터 (1 − 안전율 10%) = 90% 까지만 싣는다
```

### 4-2. ② 점수: 규칙 70% + LightGBM 수락 예측 30%

```python
def match_score(pickup_km, util, radius_km=50, w_dist=0.6) -> float:
    """0~1. 가까울수록(반경 대비), 적재함을 많이 채울수록 높다."""
    dist = max(0.0, 1 - pickup_km / radius_km)
    return round(w_dist * dist + (1 - w_dist) * max(0.0, min(1.0, util)), 4)

def _combine(self, rule, ml):
    return round((1 - ML_WEIGHT) * rule + ML_WEIGHT * ml, 4)        # ML_WEIGHT = 0.3

r["lgb_pass"] = p >= ML_THRESHOLD    # 0.75 미만이면 자동 제안 안 함 (거절될 제안을 미리 차단)
```

- **왜 헝가리안:** 화물마다 1순위 기사를 따로 고르면(그리디) 한 기사가 여러 화물의 1순위일 때 먼저 처리된 화물이 가져가 전체 품질이 떨어집니다. 헝가리안은 **모든 쌍의 점수 합이 최대**가 되는 1:1 배정을 한 번에 구합니다.
- **기준선 비교:** 라운드마다 같은 후보 안에서 `greedy`(점수순) · `nearest`(단순 최단거리)도 함께 계산해 매칭 로그에 남깁니다.

| 화물 × 기사 | 헝가리안 | 그리디 |
|---|---:|---:|
| 6 × 17 (데모) | 0.04 ms | 0.03 ms |
| 30 × 45 (스트레스 테스트) | 0.27 ms | 0.23 ms |
| 100 × 100 | 1.7 ms | 1.1 ms |
| 300 × 300 | 15 ms | 10 ms |
| 1000 × 1000 | 230 ms | 155 ms |

### 4-4. 매칭 라운드 · 분산 락 · 제안 → 수락

```python
    if not got:
        return  # 다른 워커가 배정 중 → 다음 요청 때 다시
    pending = sorted((o for o in self.orders.values() if o["status"] == "MATCHING" and not o["offer"]),
                     key=lambda o: o["posted_at"])
```

### 5-2. 디바운싱 — GPS 튐으로 경보가 울리지 않게

```python
def debounce(count, off_route, hits=3):
    """연속 이탈 횟수 갱신 → (새 횟수, 이벤트). 'ALERT'(정확히 hits 번째) · 'RECOVERED' · None."""
    if off_route:
        count += 1
        return count, ("ALERT" if count == hits else None)
    return 0, ("RECOVERED" if count >= hits else None)
```

- 계획 경로까지 거리(Shapely) > 1 km가 **연속 3번**일 때만 경보. 단발 튐 8회 → 오알람 0건, 고의 이탈 4건 → 모두 정확히 3번째 핑에서 경보.
