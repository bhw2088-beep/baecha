# 배차의 민족 실행 방법 (VS Code + Docker)

> 명령 두 줄짜리 요약은 [README 빠른 실행](../../README.md#빠른-실행-도커)에 있습니다. 이 문서는 처음 하는 사람을 위한 단계별 안내입니다.

## 받기 (둘 중 하나)

- **A. zip 으로 받았을 때** → 압축 풀기
- **B. GitHub 에서 받을 때** (비공개 저장소라 저장소 주인이 Settings → Collaborators 에서 초대해야 함)
  - PC 에 Git 이 없으면 git-scm.com 에서 설치
  - VS Code → `Ctrl+Shift+P` → "Git: Clone" → "Clone from GitHub"
    → GitHub 로그인 → `bhw2088-beep/baecha` 선택 → 저장할 폴더 선택 → Open

## 준비 (처음 한 번만)

1. Docker Desktop 실행 (작업 표시줄에 고래 아이콘이 보이면 OK)
2. VS Code → 파일 → 폴더 열기 → 받은 baecha 폴더 선택 (B 로 받아 이미 열렸으면 건너뛰기)
   (신뢰 여부를 물으면 "Yes, I trust the authors")
3. 왼쪽 확장(네모 4개) → "Container Tools" 검색 → Microsoft 것 설치
4. VS Code 터미널 열기 (`` Ctrl + ` ``) → 아래 입력
   ```
   copy .env.example .env
   ```
   왼쪽 탐색기에서 `.env` 를 열어 `POSTGRES_PASSWORD` 의 `change-me` 를 원하는 비밀번호로 바꾸고 저장 (`Ctrl + S`)
   (`DATABASE_URL` 의 `change-me` 도 같은 값으로 · 그대로 둬도 실행은 됩니다)

## 실행

5. 터미널에 입력 (처음엔 몇 분 걸림)
   ```
   docker compose up --build -d
   ```
6. 왼쪽 컨테이너 아이콘 → baecha 아래 6개가 초록색 ▶ 이면 실행 완료
   (db · redis · backend · worker · simulator · frontend)

## 화면 보기

7. 컨테이너 목록에서 frontend 오른쪽 클릭 → Open in Integrated Browser
   (또는 `Ctrl+Shift+P` → "Browser: Open Integrated Browser" → http0://localhost:8501)
8. 데모 계정 [접속] 버튼으로 로그인 · 비밀번호 `baecha1234`
   - 화주 `logistics@samsung.com`
   - 차주 `driver.kim@baecha.co.kr`
   - 관제 `admin.control@baecha.co.kr` → **관제센터 전용 로그인** http://localhost:8501/?mode=control 에서만 접속
     (일반 로그인 화면에는 관제 계정 · 링크가 없고, 관제 계정으로 일반 로그인하면 막힙니다)

`.env` 에 아래 값을 넣고 저장 → 터미널에 `docker compose up -d` (키는 GitHub 에 올라가지 않음)

- `NTS_API_KEY=` 국세청 인증키 (data.go.kr)
- `GEMINI_API_KEY=` Gemini 키 (aistudio.google.com)

## 자주 쓰는 동작

| 하고 싶은 것 | 방법 |
|---|---|
| 로그 보기 | 컨테이너 오른쪽 클릭 → View Logs |
| 끄기 | `docker-compose.yml` 오른쪽 클릭 → Compose Down (또는 터미널 `docker compose down`) |
| 다시 켜기 | `docker-compose.yml` 오른쪽 클릭 → Compose Up (또는 `docker compose up -d`) |
| 코드 수정 반영 | 터미널에 `docker compose up --build -d` |
| 데이터 처음으로 | 관제 계정 → 왼쪽 [데모 데이터 초기화] |
| KPI 목표치 측정 (주문 8,000건 이상) | `stress_8k/` 폴더의 파일을 열고 ▷ (Run Python File) — ① `1_kpi_8k.py` KPI 측정(약 6~8분) · ② `2_seeds_8k.py` 시드별 비교 · ③ `3_margin_compare.py` 상부 허용하중 여유 비교 · ④ `4_show_results.py` 결과만 보기 (도커 켜져 있어야 함, 자세히: `stress_8k/README.md`) |
| 통합 시뮬레이터 (1단계 스모크 · 2단계 효율성) | `scripts/simulator.py` 를 열고 ▷ → 1 또는 2 입력 (또는 실행 및 디버그 목록의 '시뮬레이터 1단계 · 2단계'). 시연 서버와 분리된 테스트 전용 스택(API 127.0.0.1:18000)을 새로 띄워서 기사 → 주문 → 매칭 · 수락 · 운행 → GPS 핑 순서로 측정하고, 끝나면 테스트 스택을 지움 (`--keep` 이면 남김) |
| 텔레메트리 시뮬레이터 (기사 100명 · 화주 요청 패킷) | `scripts/telemetry.py` 를 열고 ▷ — 기사 100명의 실시간 GPS 좌표 · 공차/적재 · 톤수(1~25톤) 패킷과 화주 운송 요청 패킷을 터미널 실시간 표로 보여 주고 테스트 전용 스택에 실제로 보냄 (공차 위치 → 매칭 반영, 적재 → GPS 핑, 도착 → 하차 완료). `--no-server` 는 패킷만, `--minutes` · `--order-rate` · `--time-scale` 로 조절 |
| AI 관제 실장 (Gemini · 조회 · 요약 전용) | 관제 계정 → '전국 관제 지도' 위 [AI 관제 브리핑] 칸의 채팅창에 질문 (예: '부산 상황 알려줘', '30분 이상 지연된 운행 요약해줘'). Gemini 를 쓰려면 `.env` 에 `GEMINI_API_KEY=` (Google AI Studio 무료 키) 를 넣고 `docker compose up -d backend` — 키가 없거나 무료 할당량을 넘으면 규칙 기반으로 답함. 설정 변경 · 조치는 하지 않고 어느 화면에서 하는지 안내만. API: `POST /api/v1/ai/control-tower` (관제 계정 · http://localhost:8000/docs 의 'AI Control Tower' 에서 바로 시험 — 윈도우 PowerShell 의 `curl` 은 진짜 curl 이 아니라서 `/docs` 화면으로 시험하는 게 가장 간단) |
| 운행 자동 하차 완료 끄기 | `.env` 에 `DEMO_AUTO_DELIVER=0` 넣고 `docker compose up -d` (기본은 도착하면 자동 완료 → 기사가 하차지에서 다음 배차 대기) |
| GitHub 에 올리기 | 소스 제어(가지 아이콘) → 메시지 입력 → Commit → Sync Changes |
| GitHub 최신 받기 | 소스 제어 → Sync Changes (또는 왼쪽 아래 동기화 아이콘) |

## 안 될 때

- **화면 글자가 이상함** (예: 로그인 → 입니다) → 브라우저 자동 번역 끄기: 주소창 번역 아이콘 → 원본 보기 · 이 사이트 번역 안 함
- **컨테이너 목록에 "Failed to connect · Podman"** → "Configure container runtime" → Docker 선택
- **"docker 명령을 찾을 수 없음"** → Docker Desktop 이 켜져 있는지 확인
- **화면이 안 뜸** → 1~2분 기다린 뒤 새로고침, 컨테이너가 모두 초록색인지 확인
- **"port is already allocated"** → 이미 켜진 서버를 끄고 다시 실행
