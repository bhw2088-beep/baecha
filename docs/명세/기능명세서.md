 0. 용어 · 공통 규칙
------------------------------------------------------------------------------
  화주      화물을 맡기는 기업 (예: 삼성물류)
  차주      화물을 운송하는 기사 (예: 김철수, 11톤 냉동탑차)
  관제      전체 차량·화물을 모니터링하고 매칭 실패 · 이상 상황에 대응하는 운영자
  운임      화주 희망 운임 + 관제 보조금(재공고 시 추가) = 차주가 받는 금액
  배차 제안  자동 매칭이 1순위 기사에게 보내는 제안. 수락하면 배차 확정
  e-POD     전자 화물인수증 (하차 시 인수자 서명 + 위변조 확인용 해시)
  EP        Extreme Point. 3D 적재 알고리즘이 다음 상자를 놓을 후보 위치

  [화물 상태]   매칭중 → 배차완료 → 배송중 → 운송완료 → 정산완료
                (MATCHING) (ASSIGNED) (IN_TRANSIT) (DELIVERED) (SETTLED)
  [매칭 상태]   (매칭중일 때) 기사 응답 대기(OFFERED) / 매칭 실패(FAILED) / 후보 탐색 중(SEARCHING)
  [청구 상태]   청구 필요 → 승인 대기 → 입금 완료
                (UNBILLED) (REQUESTED) (PAID)
  [이상 상태]   미해결(UNSOLVED) → 조치완료(RESOLVED)

  - 모든 API는 로그인 토큰 필요 (헬스체크·메타·로그인·회원가입 제외), 역할이 다르면 403
  - 운행 시뮬레이션 배속: 실제 1초 = 운행 20초 (위치·진행률·ETA 자동 진행)

 1. 자동 매칭 (메인)                                         backend/store.py
------------------------------------------------------------------------------
 [M-01] 매칭 시점
   - 화주가 화물을 등록하는 즉시
   - 그 뒤 모든 API 요청마다 한 번씩(tick): 제안 시간 초과 처리 → 제안이 없는 매칭중 화물에 다시 매칭
     (오래 기다린 화물부터) → 매칭 실패 화물도 공차가 생기면 자동으로 제안이 나간다

 [M-02] 후보 필터 (모두 만족해야 후보)
   ① 운행 중(배차완료·배송중)이 아님
   ② 다른 화물의 배차 제안에 응답하는 중이 아님 (기사 1명당 제안은 동시에 1건)
   ③ 이 화물을 거절했거나 응답하지 않은 적이 없음 (재공고·재매칭 시 초기화)
   ④ 빈패킹 적합: 화주가 입력한 품목 그대로, '그 기사 차량' 기준으로 3D 적재 시뮬레이션을 다시 돌려
      전량 적재 + 필수 제약(냉장 호환 포함) 통과 (차종별 결과는 화물에 캐시)
      ※ 품목 없이 등록된 화물(시드 일부)은 간이 판정: 냉장 조건 + 요청 톤수의 1~2.5배 차량
   ⑤ 상차지까지 도로거리([M-08])가 탐색 반경(기본 50km) 이내

 [M-03] 순위 (점수 높은 순, 같으면 가까운 순)
   점수 = 거리 가중치 × 거리 점수 + (1 − 거리 가중치) × 적재율      (기본 거리 0.6 / 적재율 0.4)
     거리 점수 = max(0, 1 − 상차지까지 km ÷ 탐색 반경)
     적재율    = max(부피 적재율, 중량 적재율)   ← 작은 화물에 큰 차가 배정되는 낭비를 줄임

 [M-04] 배차 제안 → 확정
   - 1순위 기사에게 제안 (제한시간 기본 60초)
   - 수락 → 배차 확정(배차완료), 매칭 기록 저장 (상차 거리 · 적재율 · 점수 · 제안 횟수 · 자동/관제)
   - 거절 또는 제한시간 무응답 → 그 기사를 제외하고 바로 다음 순위에게 제안
   - 후보가 없으면 '매칭 실패' + 원인 기록 → 관제 화면에 노출

 [M-05] 매칭 실패 원인 (자동 분석)
   - 등록 차량 중 이 화물을 전량 적재할 수 있는 차량이 없음
   - 적재 가능 차량 N대 모두 운행 중 · 다른 제안 대기 중 · 거절
   - 반경 Nkm 내 적재 가능한 공차 없음 (가장 가까운 공차 Nkm)
   - 기사 N명 거절 · 응답 없음
   - (관제 화면에서 추가) AI 적정 운임 대비 희망 운임 N% 저렴 / 등록 메모

 [M-06] 매칭 설정 (관제 '자동 매칭 분석' 화면에서 변경, [A-05])
   항목             기본값   범위
   탐색 반경        50km     10 ~ 200km (5km 단위)
   수락 제한시간    60초     15 ~ 300초 (5초 단위)
   거리 가중치      60%      0 ~ 100% (5% 단위, 적재율 가중치 = 100% − 거리)
   - 저장 즉시 매칭 대기 화물(매칭 실패 포함)에 새 기준으로 다시 매칭. 이미 나간 제안은 원래 제한시간 유지
   - 기본값은 store.py 의 DEFAULT_SETTINGS. 서버 재시작 시 기본값으로 돌아간다
   - 화주 등록 화면 · 기사 카드의 '점수 = 거리 N% + 적재율 N%' 안내도 현재 설정으로 표시

 [M-07] AI 추천 리스트 (기사가 직접 골라 수락)
   - 대상: 매칭 대기 화물 중 '내 차량에 전량 실리는' 화물 전체 (반경 밖 · 이전에 거절한 화물 포함)
   - 정렬: 같은 매칭 점수 순 (반경 밖은 거리 점수 0), 나에게 온 배차 제안은 위 카드에 따로 표시
   - 다른 기사가 자동 배차 제안에 응답 중인 화물은 잠금(맨 아래) → 응답이 없으면 풀림
   - 수락: 운행 중이 아니고 내 차량에 다 실리면 즉시 배차 확정 (매칭 기록 방식 = 'AI 추천 수락')
           나에게 온 다른 제안이 있었다면 거절로 처리하고 바로 다음 순위 기사에게 넘긴다

 [M-08] 도로 경로 · 도로 거리                                  backend/geo.py
   - 지역 키워드 좌표 · 물류 거점의 모든 조합을 OSRM(오픈스트리트맵 기반)에서 한 번만 받아
     backend/src/data/route_cache.json 에 저장 (scripts/build_routes.py) → 서버 실행 중 외부 호출 없음
   - 사용처: 상차지 거리(자동 매칭 · 추천 리스트), 운송 거리 · AI 운임, 지도 경로선,
            운행 중 차량 위치(진행률만큼 도로를 따라 이동), 관제 지도 배경 차량 이동
   - 캐시에 없는 지점(운행 중 차량의 현재 위치 등)은 가장 가까운 캐시 지점에 붙여서 계산:
       현재 위치 →(짧은 접속 구간, 직선 × 1.25)→ 가까운 캐시 지점 →(캐시 도로 경로)→ 목적지
     두 지점이 같은 캐시 지점에 붙을 만큼 가까우면 직선 × 1.25. 캐시 파일이 없을 때만 전체 직선 × 1.25

 [M-09] 주소 → 좌표 · 지역 목록                                backend/geo.py
   - 화면의 상차지 · 하차지 · 기사 주 대기 지역은 지역 드롭다운(40곳, 시 · 도 순, 입력해서 검색)
   - 서버도 목록 밖 주소는 거부 (화물 등록 · 운임 계산 · 기사 가입 → 400). 상차지 = 하차지도 거부
   - 지역 키워드 판정은 '단어 앞부분' 기준 (예: '경북 구미 국가산업단지' 의 '가산'은 단어 중간이라 무시
     → 구미로 판정. 예전에는 서울 가산동으로 잘못 잡혀 거리가 63km 로 나오던 문제 수정, 현재 196km)

 [M-10] AI 적정 운임                                           backend/pricing.py
   적정 운임 = max(차종 최저 운임, 차종 km 단가 × 도로거리)
             + 적재 중량 할증 (최대 적재량의 50% 까지 0, 100% 에서 기본 운임의 +10%, 사이는 비례)
             + 기상 · 긴급 특송 · 현장 대기 · 콜드체인 작업     (5천원 단위 반올림, 시세 범위 −7% ~ +8%)
   - 화주 등록 화면: 상차지 · 하차지 · 차종(시뮬레이션 결과) · 중량이 정해지면 자동 계산 → 희망 운임에 자동 입력
   - 화물마다 등록 시점 기준으로 한 번 계산해 저장 (fare_est) → 기사 제안 카드 · 추천 카드 · 관제 매칭 실패 조치에 표시
   - 기사 카드: 제시 운임과 비교 (적정가보다 N% 높음 / 적정가 수준 / N% 낮음), km당 운임

 [P-01] 알고리즘: 적재 규칙(Rule) + Extreme Point 탐색 (Crainic·Perboli·Tadei 2008 기반, 외부 라이브러리 없음)

  - 평택 → 원주 냉동식품    : 김철수가 이미 거절 → 매칭 실패 (재공고하면 다시 제안)
  - 인천항 · 대전 출발 화물 : 반경 밖이라 자동 제안은 없지만 김철수의 AI 추천 리스트에서 직접 수락 가능
  - 삼성물류 운행 중 차량 12대 (기사 D-009~D-016 은 모두 운행 중)
  ※ 제안 제한시간은 실제 시간 60초. 서버를 켜고 늦게 접속하면 첫 제안은 이미 넘어가 있을 수 있다
    → 관제 '매칭 실패 조치'에서 재매칭하거나, 화주로 평택/동탄 상차 화물을 새로 등록하면 된다.

------------------------------------------------------------------------------

    → 지역을 늘리려면 geo.py 의 REGION_COORDS · REGION_LABELS 에 추가하고 scripts/build_routes.py 를 다시 실행

  - 도로 경로는 일반 차량 기준 (화물차 높이 · 중량 제한 미반영). 운영 시 TMAP 화물차 경로 등 검토

  - 차량 제원은 국내 표준형 근사치 (실제 차량 정보로 교체 필요)
  - 실시간 갱신은 주기적 재조회 방식 (대규모 운영 시 WebSocket/푸시 전환 검토)
