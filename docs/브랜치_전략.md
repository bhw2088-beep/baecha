# 브랜치 전략 · 배포 흐름

> 저장소: GitHub `bhw2088-beep/baecha` (비공개) · CI: GitHub Actions (`.github/workflows/ci.yml`)

## 1. 브랜치

| 브랜치 | 용도 | 누가 · 어떻게 바뀌나 | 배포 |
|---|---|---|---|
| `main` | **운영(프로덕션)** 코드. 항상 실행 가능한 상태 | `staging` 에서 검증된 것만 Pull Request 로 머지 | `docker-compose.prod.yml` 로 배포 |
| `staging` | **통합 검증(시연 · QA)**. 다음 배포 후보 | `feature/*` · `fix/*` 를 Pull Request 로 머지 | 시연 PC / 검증 서버에 `docker compose up --build -d` |
| `feature/<기능>` | 새 기능 하나 (예: `feature/pod-photo`, `feature/payout`) | `staging` 에서 따서 작업 | 로컬 도커로만 |
| `fix/<버그>` | 버그 수정 | `staging` 에서 따서 작업 | 로컬 |
| `hotfix/<긴급>` | 운영 긴급 수정 | `main` 에서 따서 → `main` 과 `staging` 에 모두 머지 | 바로 운영 |

```
feature/payout ─┐
feature/pod-photo ─┼─▶ staging ──(검증 · 시연)──▶ main ──▶ 운영 배포
fix/map-panel ──┘          ▲                       │
                           └──── hotfix/xxx ◀──────┘
```

## 2. 규칙

1. `main` · `staging` 에 **직접 커밋하지 않는다** — 항상 Pull Request.
2. Pull Request 는 **CI 통과**(pyflakes · 점검 스크립트 8종 · 도커 통합 스모크)가 머지 조건.
3. 머지 방식: `feature → staging` 은 Squash merge(기능 단위 커밋 1개), `staging → main` 은 Merge commit(배포 이력 보존).
4. `main` 머지 시 태그를 단다: `v<년>.<월>.<순번>` (예: `v2026.11.1`).
5. 비밀값(`.env` · API 키)은 어떤 브랜치에도 올리지 않는다 (`.gitignore` · `.dockerignore`).
6. DB 구조가 바뀌는 변경(컬럼 추가 등)은 서버 시작 시 자동 반영되도록 `core/database.py` `create_tables` 에 함께 넣는다.

## 3. CI (`.github/workflows/ci.yml`)

| 이벤트 | 실행 |
|---|---|
| `main` · `master` · `staging` 에 push | lint-test (3.12 · 3.14) → integration (docker compose + 스모크) |
| 모든 Pull Request (`feature/*` → `staging` 등) | 같은 검사 |

## 4. 배포 (무중단에 가깝게)

```bash
git checkout main && git pull
docker compose -f docker-compose.prod.yml build            # 새 이미지 먼저 빌드 (서비스는 그대로 동작)
docker compose -f docker-compose.prod.yml up -d --no-deps frontend   # 화면부터 교체
docker compose -f docker-compose.prod.yml up -d --no-deps worker
docker compose -f docker-compose.prod.yml up -d --no-deps backend    # 백엔드는 1프로세스라 수 초 끊김
```

> 참고: GitHub 무료 비공개 저장소는 **브랜치 보호 규칙**을 쓸 수 없다. 위 1 · 2번 규칙은 팀 약속으로 지키고,
> 유료 요금제나 공개 저장소로 바꾸면 `main` · `staging` 에 "PR 필수 · CI 통과 필수" 보호 규칙을 건다.
